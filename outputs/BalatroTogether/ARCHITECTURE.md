# Architecture / release status

Version 0.6.1-dev is a testing release. It uses independent native Balatro simulations with host-authoritative shared progression and score accounting. It is not a host-side implementation of all Balatro rules, and cannot verify a malicious client's joker calculation.

`core/session.lua` is the pure state reducer; `net/thread.lua` owns nonblocking TCP sockets in a LÖVE worker; `net/client.lua` authenticates private-room handshakes, maps sockets to seats, retries transient connections, orders commands and distributes snapshots. `game/bridge.lua` adapts native gameplay; `ui/interface.lua` draws the original UI. Networking never executes received Lua.

The room has fixed seats 1–4. A run starts only at the configured player count, with everyone ready. Each seat has its own ordered sequence and acknowledgement watermark. Repeated messages have no effect. Round IDs and hand numbers reject stale or repeated scores. The host controls seed, blind identities, targets and outcomes. Each player owns its deck, purchases, RNG and joker calculations; public build snapshots are for inspection, not remote control.

Fast Restart is a host-owned deliberate cancellation. It retains seats, TCP connections, tokens, acknowledgements and difficulty; increments the run ID; resets run statistics; distributes the fixed custom seed or a fresh random seed; and runs native start_run on each client, which clears its previous native event queue. Every action includes its run ID. Delayed packets from an older run are acknowledged/rejected without modifying the fresh run. Pending old-run callbacks cannot play a hand in a new epoch. Disconnected active seats must reconnect or be retired first.

Phases: lobby → prepare (all native blind screens ready) → blind (simultaneous play) → shop (team success) → prepare; ante 8 boss success → shop → ante 9 by default (victory only for an explicitly finite model); exhausted table → defeat. Busy scoring actions delay completion. Disconnection pauses shared transitions. The host can retire a disconnected seat. There is no host migration or process-restart recovery.

Each blind's target = ceil(native target × active players^1.08 × difficulty). Difficulty defaults to 1.0. Each player receives their native blind reward, unused-hand money and interest. Shops are independent. Skips, boss rerolls and ante-changing vouchers are disabled. Boss identity is explicitly supplied by the host; effects act on each player's own board. Local blind disable effects remain local. No team-combo bonus is enabled.

Steam mode uses friends-only lobbies and reliable ordered ISteamNetworkingMessages on channel 27 through the game's initialized steam_api64.dll and its real Balatro App ID. The original FFI bridge never initializes/shuts down Steam itself, replaces libraries or changes authentication. Two persistent callback objects handle lobby/presence invites; the game thread polls async lobby results and message queues without blocking. Members are admitted from the actual lobby, Steam IDs stay exact uint64/decimal strings, reconnect secrets are bound to Steam identities, and each packet names its lobby to reject stale-room traffic. Host loss fails explicitly rather than migrating unsynchronized game authority. Steam hosts retain a loopback-only ephemeral TCP listener for native bots. Direct IP remains an optional unencrypted TCP transport (default 24872) with six-digit PINs and host router forwarding as needed.

Privacy: hidden hands are omitted by default. A player may explicitly reveal their current hand. Disabling inspection omits their build/board/shop details from host snapshots. Local deck order, unrevealed shop rolls and private cards never become remote gameplay commands.

Native bot companions are host-managed Windows processes with isolated Mods/log/save identities. The pinned Steamodded, Cryptid, Amulet and Together components are copied into each companion cache. A reserved reconnect token binds each bot to its host-created seat; the ordinary protocol orders its native contributions. bots/strategy.lua is a side-effect-free expected-score/discard/shop heuristic; bots/controller.lua drives native UI actions after event/lock checks; bots/process.lua launches the owned executable with an isolated environment and watches process handles. No shell or external inference service is used.

Session snapshots carry the host-selected vanilla deck key and optional custom seed. Native start_run uses that deck on every human/bot client. Fixed-seed Fast Restart repeats the seed; random mode generates another. White Stake and co-op progression restrictions remain.

`core/donations.lua` owns bounded, data-only card validation and an eight-item escrow ledger. `game/donations.lua` removes a donor's native ownership before offering, restores a rejected deposit, constructs a recipient's native card once, then commits the reservation. Receipts live in snapshots so a lost acknowledgement does not roll back an accepted deposit. Action sequence numbers and run epochs supply transport idempotence. Commit history and recipient item IDs prevent duplicate construction/commit. Only the reserved recipient gets a full payload; other snapshots carry summaries. Restart discards the old ledger. This is in-memory, same-process recovery, not durable transactional storage or anti-cheat.

Claim reservations mark the recipient as transferring and block ready/progression. Local pending transfers guard native inventory actions. Native add/remove effects run on the appropriate owner; editions are set before restoring Steamodded's saved ability slot totals to avoid double Negative slot bonuses. Constructor failures roll back and cancel the reservation. `ui/donations.lua` renders native atlas previews without distributing game assets; `ui/motion.lua` provides bounded, substepped damped springs and transfer arcs.

0.3.1 progression: prepare → starting → blind. Starting selects the native blind on every client and waits for matching round/ante/slot/key entry acknowledgements before accepting gameplay. Shop progression requires explicit native exit acknowledgements for the expected next position, rather than accepting a generic Ready as evidence of completed native events. Cash-out records the native completion boundary once, and canonical slot states prevent stale Current markers from changing Steamodded blind classification.


Bet Pot: `core/pot.lua` owns the bounded host ledger (`bank`, next-blind `wager`, seat contributions, volume and settlement round). Session settles it once when the shared blind ends. Each seat's monotonically increasing deposit transaction and latest persistent receipt deduplicate accepted and rejected attempts. `game/pot.lua` synchronously debits the native wallet before requesting deposit, refunds rejection once, and applies only the difference between cumulative host credits and the locally applied total. A cumulative receipt releases ready/shop barriers after native delivery. Money changes use the native instant money helper, never a replayable queued delta or a full-wallet overwrite. `ui/pot.lua` draws original vector shapes and uses the shared damped spring implementation. Saved winnings do not roll into the next bet automatically. All pot state is run-scoped and discarded on restart.


Reward dice: `core/dice.lua` owns run-scoped per-seat tickets, current throws, gold credit totals and queued/active Mult. `core/dice_physics.lua` runs fixed 1/240-second cube and icosahedron contact simulation. Only seeds/final poses/results cross the wire; `game/dice.lua` replays local frames, commits finished rolls, delivers native gold once and acknowledges cumulative credits. The host activates queued Mult at begin_blind, clearing it for subsequent blinds. A native Blind.modify_hand wrapper adds only the active matching shared round's Mult before the original modifier chain. `ui/dice_renderer.lua` creates procedural faces and cached number textures; `ui/dice.lua` draws spring controls and visual effects. No game art is stored in the mod. Session gates ready/shop/restart on unresolved dice/payouts, and normal pot/donation actions respect the same local money/action locks.


The Boss Reward Wheel uses `core/boss_wheel.lua` for deterministic host spin trajectories and final pointer slots, with `core/boss_rewards.lua` providing the 21 positive packages. `core/dice.lua` owns tickets, prize receipts and queued/active blind effects. `game/dice.lua` delivers native hand levels and banked free rerolls with per-effect checkpoints; extra hands/discards apply once per native blind and chip/Mult injections feed the native Blind hook. `ui/dice.lua` renders the wheel, public prize table and teammate replays. There are no percentile-die assets or external art dependencies.


`core/admin.lua` authorizes the pinned owner Steam ID against the seat identity assigned by the transport, then restricts preset grants and recovery operations. The host's own identity comes from the native Steam API; remote Steam identities come from verified peers, and TCP guests cannot self-assert them. `game/admin.lua` checks the local identity for the shortcut and processes broadcast native-handshake retries. `ui/admin.lua` renders targeted grants and explicit restart/retirement confirmation. Admin grants reuse reward credit/effect receipts. Restart acknowledgements are written to the new player record so the next command's sequence remains valid.

The host captures native run-selection defaults and distributes setup_choices with the run. Each adapter fills both RunSelect.Setup.choices and profile.last_choices before applying a deck. Personal pots use the same ordered deposit and cumulative native payout receipts as the team pot; personal collection is always attributed to the acting seat. The optional wheel challenge uses host time and distinct-key counters, then returns to the ordinary wheel replay/reward delivery path.
